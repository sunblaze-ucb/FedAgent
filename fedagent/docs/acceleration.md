## Why the loop is slow without help

The faithful federated loop runs **one verl subprocess per (client, round)**: every client of
every round pays a full engine cold-start (Ray cluster up, vLLM engine load + CUDA-graph
capture, FSDP wrap, initial weight transfer) before its first training step, and tears it all
down after (**~310 s per client-fit at the 1.5B paper config**). On top of that: each round
restarts its clients' env services from scratch (ALFWorld's warm-up alone walks an 8810-game
directory tree), the final eval spins up its own cold engine, and every round runs a
FedAvg-merge-to-HF pass. Measured on GPU: **~76–88 % of wall-clock was startup/teardown, not
training**. The training step itself is already efficient (the async agent loop keeps the
episode critical path saturated), so all the acceleration comes from **not re-paying fixed
costs**, never from touching the numerics.

## How: the final recipe

```yaml
cross_round: true        # ONE trainer + vLLM process for the whole run, not per (client, round)
eval_mode: worker        # score each round's aggregate on that same hot engine
service_scope: run       # keep each client's env services warm across rounds
final_eval_mode: worker  # score the final model on the hot engine too (no cold subprocess)
hf_export: final         # skip per-round HF merges; round r+1 reloads aggregated FSDP shards
# ALFWorld (env-bound) add:   alfworld_replicas: 8, alfworld_manifest_cache: true
# WebShop (GPU-bound) add, via client_overrides:
#   - actor_rollout_ref.model.use_fused_kernels=True
#   - actor_rollout_ref.model.fused_kernel_options.impl_backend=triton
```

Ready to run: **every `config/paper/**` cell has an accelerated twin** at the same relative
path under [`config/paper_accelerated/`](../config/paper_accelerated/) (generated by
`gen_paper_configs.py --accel`; per-GPU-count guidance: [gpu_recipes.md](./gpu_recipes.md)).
The twins keep `hf_export: every_round` so round-level resume works; flip to `final` by hand
for this recipe's merge-skip. The original A/B artifacts remain on the `migrate/verl-0.8.0` branch:
[`accel/alfworld/paper_alf_combo.yaml`](https://github.com/sunblaze-ucb/FedAgent/blob/migrate/verl-0.8.0/tools/verl08_migration/accel/alfworld/paper_alf_combo.yaml)
/ [`accel/webshop/paper_ws_combo.yaml`](https://github.com/sunblaze-ucb/FedAgent/blob/migrate/verl-0.8.0/tools/verl08_migration/accel/webshop/paper_ws_combo.yaml).
Every knob is **optional and default-OFF**: an untouched config runs the original,
byte-identical path.

**Result (real 1.5B paper configs, GPU-measured):** steady round **1125 → 762 s** (ALFWorld)
and **905 → 402 s** (WebShop); full 70-round budget **~41 h → 16.7 h (×2.5)** and
**~32 h → 9.4 h (×3.5)**.

**Composition gates** (enforced at startup, `run_fed.py`): `hf_export: final` needs
`persistent`/`cross_round` **and** worker-or-disabled eval; `final_eval_mode: worker` needs
`cross_round` + `eval_mode: worker` (else it warns and falls back); `one_step_off` is
subprocess-path-only and excludes `parallel_clients>1`; `prewarm_next_round_services` is
redundant (ignored) under `service_scope: run`.

## Why each lever works

| lever | what it removes | measured effect |
|---|---|---|
| `persistent` / `cross_round` | the engine cold-start per (client, round), **the dominant term**. One process stays up; each client-round reloads its starting weights exactly as a fresh process would | loop time **−43 % / −62 %** (per-round / cross-round prototype A/Bs) |
| `eval_mode: worker` | the eval engine's own cold-start, every round (eval = generate + score on the same val code path, just on the hot engine) | ALFWorld eval-mode sweep: worker **3509 s** vs inline **4738 s** |
| `alfworld_replicas: K` | the env service's engine lock: ALFWorld steps serialize at ~86 ms inside one process. K OS processes shard the sessions round-robin (K=1 is byte-identical; partition/seed unchanged) | gen **217.5 → 61.8 s**, step **−57 %** (4-GPU) |
| `alfworld_manifest_cache` | the ~270 s/round 8810-game directory walk (caches the **pre-shuffle** list; self-validating key; degrades to the walk, never to wrong data) | **−18 %** |
| `service_scope: run` | per-round env-service restart + warm-up (fleets are health-checked before reuse; LRU-capped) | **−16 %** |
| `final_eval_mode: worker` | the cold final-eval subprocess | **−11 %** |
| `hf_export: final` | the per-round FedAvg-merge-to-HF pass (shard-direct reload ≡ merge path, A/B 8.8e-6) | inside the all-four **−24 %** |
| fused kernels (WebShop) | logprob/entropy memory traffic in the GPU-bound step (stock verl option) | WebShop **−6.5 %**; ALFWorld wash |

**Measured and rejected**, knowing what *doesn't* work is part of the why:
`use_dynamic_bsz` (slower on **both** envs: the GPU term is FLOP-bound and shape churn defeats
CUDA-graph reuse); WebShop `webshop_replicas` (probe gain didn't survive at paper scale:
cold-probe arithmetic is ~3× pessimistic vs hot-engine steps); `parallel_clients` lanes on one
node at 1.5B (wash on top of this stack: the fit is GPU-bound, so 2 clients × 2 GPU ≈
sequential 4-GPU; lanes remain the **multi-node** lever, see
[running.md](./running.md#sequential-vs-parallel-clients)); `one_step_off` (−10 % realized but
**off-policy**, never for paper runs).

## Why it's safe (the equivalence bar)

The project bar is *scientific equivalence first, speed second*: every knob was A/B'd on GPU
against the legacy path and the **final aggregated models compared parameter-by-parameter**.
The measured GPU-nondeterminism floor (same config, run twice) is **max|Δ| = 9.293e-5**, and
every knob landed at or below it: manifest cache 9.199e-5, service scope 9.090e-5, worker
final-eval 9.241e-5, all-four 8.752e-5, hf_export 8.825e-6, lanes 1.144e-5, fused 1.116e-5.
Real-env persistent-vs-subprocess A/Bs: WebShop **GRPO actor 9.8e-6**, **PPO actor 1.16e-5**.
(When reading a PPO critic A/B: the value head `score.weight` is freshly random-initialized
per run, so a ~5.9e-2 delta **on that one tensor** is expected and harmless; don't read it as
divergence.)

## What still costs time

With the fixed costs gone, **eval cadence** is the biggest remaining term: one n=500 WebShop
eval (~630 s) costs more than a steady training round (402 s). The aggregated model is scored
every round by design; decide `client_end_eval` (the figures' per-client circles, +M
evals/round; paper configs ship `true`) deliberately, before launching.

## New environment? The 30-second rule

Run one training step at **two GPU counts** and read the gen term of `timing_s`:
**gen flat across GPU counts ⇒ env-bound** → add `<env>_replicas` (K≈4–8) before adding GPUs;
**gen scales with GPUs ⇒ GPU-bound** → GPUs first, replicas are garnish. Either way, don't
starve clients to 1 GPU. ALFWorld and WebShop turned out to be exact mirror images of this
rule; full decision procedure and the cross-env caveats: archive §10.5.
